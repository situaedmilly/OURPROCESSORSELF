# GITHUBCOMPUTERMORPH v0.6 — CAUSAL ACTUATOR INTEGRATION

Flow:
MESSAGE → PROPOSAL → ADMISSION → INSTANCE → PROCESSOR → PROCESSOR RECEIPT → SEALED EVIDENCE → TRANSITION RECEIPT → ACTUATION REQUEST → ACTUATOR ADMISSION → UPDATE_REF → READ-BACK → ACTUATOR RECEIPT → ACTUAL REPOSITORY STATE.

Invariant:
NO ACTUATOR RECEIPT = NO CLAIM OF PHYSICAL REPOSITORY TRANSITION.

Failure:
ACTUATOR_FAILED → no actual repository state object → previous observed state remains authoritative.

Scope: UPDATE_REF only. No merge. No GitHub Actions dependency.
